## Key Findings

### 1. Cascade Routing: Cheap-First with Quality Escalation
- **Pattern**: Route query to cheapest capable model first. If output fails a quality gate (empty response, low confidence, invalid schema), escalate to next tier.
- **Quality gate examples**: response length, JSON parse success, schema validation, keyword presence.
- **Cost savings**: 40-70% reduction in LLM spend by using cheap/free models for 60-80% of queries, only escalating the hard ones.
- **Agent-specific**: In A2A dispatch, the cheapest model (nemotron-3.5-lightning-free) handles most briefs. If it returns empty `content` (thinking model issue) or fails validation, escalate to a stronger model (local LM Studio).
- **Two-tier cascade**: Model A (free) → Model B (paid/local) → Model C (frontier, rarely needed).
- **Fallback routing vs cascade**: Fallback handles unavailability; cascade handles quality. A2A needs both — fallback when model endpoint dies, cascade when model returns bad output.

### 2. Multi-Agent Orchestration: 5 Production Patterns
- **Orchestrator-Worker**: Central hub delegates subtasks to specialists, aggregates results. (This is what A2A already does.)
- **Swarm**: Decentralized emergent coordination — agents self-organize, no central controller. Good for exploration but hard to debug.
- **Mesh**: Direct peer-to-peer communication between agents. Complex but flexible.
- **Hierarchical**: Tree-structured delegation — top-level supervisor → mid-level supervisors → workers. Best for large agent fleets (55+ game-studio agents).
- **Pipeline**: Sequential stage-based processing. Each agent's output feeds the next agent's input. Good for refinement tasks (draft → review → polish).
- **Implication**: Current A2A uses Orchestrator-Worker. Could add Hierarchical for the 55-agent fleet — group agents by domain (graphics, gameplay, audio, QA) with domain-level dispatchers.

### 3. Testing Non-Deterministic Systems
- **Problem**: AI agents produce different outputs for identical inputs. Unit tests pass/fail nondeterministically.
- **Sources of non-determinism**: Model temperature, context window state, external API changes, floating-point precision, timing.
- **Solutions**:
  1. **Statistical testing**: Run N times, compute pass rate, assert pass rate ≥ threshold (e.g., ≥ 80%).
  2. **Confidence intervals**: Report score ± margin of error at 95% confidence.
  3. **Fixed seeds**: Set random seeds where possible (model inference still varies but deterministic given same input).
  4. **Tolerance bands**: Assert values within ±5% of expected, not exact equality.
  5. **Snapshot testing with tolerance**: Compare against baseline with fuzzy matching.
- **For game QA**: Perception state (OCR text, scene classification) varies across runs. Tests should assert that the agent correctly classified a scene ≥ X% of the time over N trials.
- **Statistical significance**: Use chi-squared or bootstrap to compare two agents' performance, not just raw scores.

### 4. Visual Drift Detection for Perception Stability
- **CSS Selector Drift Detection** pattern: Monitor when UI element selectors break due to layout changes.
- **Implication for UGAFStudio**: Game perception (template matching, color detection) can "drift" when game updates change textures, UI layout, or rendering settings. A `PerceptionDriftDetector` could:
  1. Hash reference screenshots (perceptual hash)
  2. Compare live frames against reference hashes
  3. Alert when drift exceeds threshold (game updated, rendering changed)
  4. Auto-retrain perception templates from new screenshots

### 5. Herdr: Runtime for Coding Agents
- **Herdr** (herdr.dev, 2026): Runtime that holds real terminals open on laptop/desktop, survives lid closing, reattach from anywhere.
- **Implication**: Similar to our background process pattern for OpenCode dispatch. Could be a more robust alternative to `subprocess.Popen` for long-running agent processes.

## Synthesis: CascadeDispatchRouter + PerceptionDriftDetector + StatisticalTestRunner

### Component 1: CascadeDispatchRouter
- Extends existing A2A dispatch with model escalation logic.
- Dispatch brief → Model A (free) → validate output → if bad, escalate to Model B.
- Quality gates: non-empty content, JSON parseable, has required sections, reasonable length.
- Tracks cost savings: counts tokens/models used, reports estimated cost.
- Fallback chain for endpoint unavailability (timeout/connection error).

### Component 2: PerceptionDriftDetector
- Perceptual hash (pHash) of reference game screenshots.
- Compare live frames against reference hashes during test runs.
- Configurable drift threshold (default 0.85 similarity).
- On drift: log warning, optionally trigger template retraining.
- Useful for detecting game updates that break perception.

### Component 3: StatisticalTestRunner
- Run a game QA scenario N times (default 10).
- Aggregate pass rates with 95% confidence intervals.
- Assert pass rate ≥ threshold (configurable, default 0.8).
- Report: mean score, std deviation, min/max, pass count/total.
- Useful for validating agent reliability, not just single-shot success.
